# SparkChat 需求与验收规范

本文档描述当前代码已经提供的功能、接口契约和验收边界。它既是产品需求基线，也是后续修改前端或后端时用于防止行为回退的检查清单。

## 1. 产品定位

SparkChat 是面向移动设备的可安装 PWA 数字角色对话应用。用户登录后可以选择预置角色或创建自己的角色，进行多轮文本聊天、语音输入、文本朗读和端到端实时语音通话。前端为无构建步骤的原生 ES Modules，后端为 Flask 应用，数据存储在 SQLite。

## 2. 账号与权限

- 支持账号密码注册、登录和退出。
- 本地数据库初始化时提供体验账号 `CaraLin`，密码 `2766`；部署数据是否保留该账号取决于数据库状态。
- 本地数据库初始化时提供管理员账号 `Admin`，初始密码为 `123`。已有 `Admin` 账号初始化时只补充管理员标记，不覆盖管理员已经修改的密码。
- 用户名长度为 3 至 24 个字符，密码长度为 4 至 128 个字符；用户名不区分大小写且不可重复。
- 登录和注册成功后创建永久会话 Cookie。生产环境必须固定 `FLASK_SECRET_KEY`，并设置 `COOKIE_SECURE=true`。
- `GET /api/auth/me` 未登录时返回 `200` 和 `{"user": null}`；其他业务 API 未登录时返回 `401` 和 `{"error":"请先登录"}`。
- 自定义角色、对话、消息、翻译缓存和语音缓存按用户隔离。
- 预置角色对所有用户可见，但每个用户可以通过覆盖记录保存自己的名称、身份背景、头像、语言和音色配置。
- 管理员可以在“我的”页面打开用户管理，查看用户列表、添加普通用户、为用户设置新密码和删除普通用户；管理员不能删除自己或其他管理员。用户列表不得返回密码哈希。

## 3. 角色与音色

### 3.1 角色字段

新建和编辑角色实际提供以下字段：

1. 头像：可使用 `/assets/` 路径或 JPEG、PNG、WebP 的 base64 Data URL。
2. 角色名称：最多 40 个字符。
3. 身份背景：最多 2400 个字符，用于描述角色身份、经历、性格、价值观和表达方式。
4. 回答语言：`zh`（中文）或 `en`（英文）。新建角色默认中文，威震天默认英文。
5. 角色音色：从后端系统音色目录选择。

角色语言固定作用于提示词和实时通话，不根据用户当前输入自动切换。旧数据库列可以暂时保留用于迁移兼容，但新界面和提示词构造只依赖上述当前字段。

- 角色配置弹窗对自定义角色提供删除操作。删除需要二次确认，并级联删除该角色的对话、消息、翻译缓存和语音缓存；预置角色不可删除。

### 3.2 预置角色和系统音色

- 当前预置角色为威震天。其身份背景基于跨作品共同设定和 IDW 2005 主宇宙经历，不写入思考模式开关或系统控制语句。
- 当前系统音色目录由后端维护，现有初始化数据包含“赛博统帅（英文）”音色。多个角色可以复用同一系统音色。
- 系统音色是只读资源，不提供音色设计、声音复刻、训练状态、个人音色库、试听、重命名或删除功能。
- 创建和编辑角色时，后端校验 `voiceId` 必须属于系统目录，并以目录中的名称覆盖客户端传入的 `voiceName`。
- TTS 和实时语音均读取当前角色最终生效的 `voiceId`；不使用全局角色音色环境变量。

## 4. 提示词与模型调用

角色指令由以下内容组成：

```text
角色指令 = 角色名称 + 身份背景
最终系统提示词 = 固定语言规则 + 角色指令 + 通用对话规则
```

- 中文角色必须用中文回答，英文角色必须用英文回答；除准确性需要外，不因用户换语言而切换。
- 通用规则负责角色一致性、回答长度、表达方式、知识边界和舞台提示使用方式；这些规则不得出现在角色配置字段中。
- 文本回复调用 Ark 模型，默认模型为 `doubao-seed-character-260628`，可由 `ARK_MODEL` 覆盖。
- 后端调用文本模型时传入 `thinking.type=disabled`；该参数属于 API 调用参数，不得把“关闭思考”或“不展示思考过程”等控制语句写入角色提示词。
- 实时通话使用不含舞台提示规则的角色指令，并额外发送对应语言的 `speakingStyle`。

## 5. 页面与对话流程

### 5.1 页面

- 登录页支持登录和注册，并显示体验账号提示。
- 联系人首页显示角色头像、名称、最近消息和最近消息时间，支持按角色名称或最近消息搜索；当前不显示未读数量。
- 首页底部导航包含联系人、新建角色和我的。
- 聊天页不显示底部导航，顶部提供返回、历史对话、角色配置和实时通话入口。
- 我的页面显示当前用户名和退出按钮，两者保持清晰间距。
- 页面在移动端和窄桌面视口不得横向溢出或出现文字重叠；图标按钮必须提供无障碍标签。

### 5.2 对话

- 每个角色可以有多个独立对话；用户可以新建、切换、重命名和删除对话。
- 首次发送消息时自动创建对话；未手动命名的对话使用首条用户消息前 80 个字符作为标题。
- 对话标题长度为 1 至 80 个字符。
- 单条用户消息长度为 1 至 4000 个字符；模型只接收当前对话最近 24 条消息。
- 用户消息使用气泡显示，不显示“你”“You”或其他身份标签。
- 助手消息支持复制、翻译、重新生成和朗读。翻译结果按用户和消息缓存，重新生成后会清理该消息的翻译与语音缓存。
- 用户消息可以点击进入行内编辑，编辑后重新发送。服务端生成新回复成功后，保留被编辑用户消息的 ID，删除该消息之后的旧聊天历史并插入新的助手回复；模型生成失败或并发冲突时原历史保持不变。
- 文本回复通过 SSE 增量返回 `delta`，结束时返回 `done`；上游异常通过 SSE `error` 事件返回，不改变已经建立的 HTTP 状态码。
- 多行输入框支持浏览器原生垂直拖拽；聊天发送操作区保持稳定，不因输入框拖拽破坏布局。

## 6. 语音能力

### 6.1 语音输入与文本朗读

- 语音输入通过豆包实时语音代理完成 ASR，不使用浏览器系统 SpeechRecognition。浏览器采集单声道音频并重采样为 16 kHz PCM16；识别结果合并到输入框，不自动发送。
- 文本朗读使用豆包 V3 HTTP Chunked TTS，资源为 `seed-icl-2.0`，模型为 `seed-tts-2.0-expressive`，输出为 24 kHz MP3，默认语速为 `-8`。
- 模型可以使用简短括号、方括号、书名括号或星号舞台提示表达动作、心理或细微表情，但不得用提示代替回答或连续堆叠。
- TTS 不直接读出舞台提示，而是将其转换为 `<cot>` 分段语音标签。
- 消息朗读只接受当前消息原文或已缓存译文；自由文本朗读不写入消息语音缓存。
- 消息语音和翻译缓存按用户保留最近 20 项；音色、语言或文本变化会导致语音缓存失效。
- 未配置 API Key 或角色无有效音色时返回 `503`；授权、额度或并发错误返回 `503` 并附带豆包控制台地址；其他上游合成错误返回 `502`。

### 6.2 实时语音通话

- 浏览器通过同源 WebSocket 连接后端实时代理，由服务端连接豆包端到端实时语音 API；API Key 不得暴露给浏览器。
- 通话界面显示角色头像、连接状态、双方字幕、输入/输出音量状态、麦克风静音和挂断控制。
- 输入为 16 kHz 单声道 PCM，输出为 24 kHz PCM16。
- `ICL_uranus_` 音色使用实时模型版本 `2.1.0.0`；`S_`、一般 `ICL_`、`saturn_`、`sparkchat_` 和 `custom_` 音色使用 `2.2.0.0`。
- 实时配置接口返回 WebSocket 地址、资源 ID、角色 speaker ID、语言、角色指令和 speaking style，不返回供应商访问令牌。
- 实时代理默认监听 `127.0.0.1:3101`；缺少 API Key 或有效音色时，配置接口返回 `503`。

## 7. PWA 与离线边界

- manifest 使用相对 `start_url` 和 `scope`，应用模式为 `standalone`，方向为竖屏，并提供 192 和 512 像素图标。
- Service Worker 预缓存应用壳；导航请求网络失败时回退到 `index.html`；其他同源静态 GET 使用 network-first，成功后写入缓存。
- `/api/` 请求、非 GET 请求和跨域请求不进入 Service Worker 缓存。
- PWA 安装和 Service Worker 仅在 HTTPS 或 `localhost` 安全上下文启用。
- 当前聊天页从 jsDelivr 动态加载 Lucide 图标模块，因此完全断网时该依赖可能无法加载；离线能力仅保证应用壳回退，不承诺离线聊天或完整离线页面交互。

## 8. 主要接口契约

- 认证：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`。认证用户对象包含 `id`、`username`、`isAdmin` 和 `createdAt`。
- 管理员：`GET/POST /api/admin/users`、`PATCH /api/admin/users/<user_id>/password`、`DELETE /api/admin/users/<user_id>`。管理员 API 对普通用户返回 `403`。
- 资源：`GET/POST /api/characters`、`PATCH/DELETE /api/characters/<id>`。只有自定义角色所有者可以删除角色，预置角色删除返回 `409`。
- 对话：`GET/POST /api/characters/<id>/conversations`、`PATCH/DELETE /api/characters/<id>/conversations/<conversation_id>`、`GET .../messages`。
- 聊天：`POST /api/characters/<id>/chat`、`POST /api/characters/<id>/messages/<message_id>/regenerate`、`POST /api/characters/<id>/messages/<message_id>/rewrite`。聊天 SSE `done` 事件包含助手 `messageId` 和用户 `userMessageId`。
- 翻译与朗读：`POST .../translate`、`POST .../messages/<message_id>/speak`、`POST .../speak`。
- 实时配置：`GET /api/token?characterId=<id>`。该名称沿用现有前端契约，返回的是实时会话配置而非访问令牌。
- 不存在角色、对话或无权访问资源时返回 `404`；字段、长度、语言、头像或音色校验失败时返回 `400`；重复账号返回 `409`；不满足重新生成条件时返回 `409`。

## 9. 验收测试

### 9.1 已有自动化检查

```powershell
python -m unittest -v tests.test_app
node tests/frontend/doubao-realtime.test.mjs
Get-Content frontend/scripts/main.js | node --input-type=module --check
Get-Content frontend/service-worker.js | node --input-type=module --check
```

后端测试使用 fake Ark、TTS 和实时客户端验证账号、Cookie、预置角色、角色私有性、角色编辑、预置角色覆盖、对话 CRUD、提示词、模型参数、翻译缓存、语音缓存、TTS 错误映射、实时配置和音色一致性。前端 Node 测试覆盖实时字幕增量合并和句末标点处理。上述测试不访问真实豆包、Ark 或真实 WebSocket，也不等同于浏览器端到端测试。

### 9.2 浏览器人工验收

- 检查登录、注册、退出、联系人搜索、新建角色、角色编辑、我的页面和多对话管理。
- 使用 `Admin / 123` 登录，检查“我的”页面的用户管理入口；添加用户、设置密码、删除用户，并确认普通用户不能访问管理员 API。
- 在自定义角色配置弹窗中确认删除按钮和二次确认；确认预置角色配置弹窗不显示删除按钮。
- 确认新建和编辑页面包含头像、角色名称、身份背景、回答语言和角色音色，且没有音色设计或 `input[type=range]` 入口。
- 检查用户消息无身份标签，点击用户消息可行内编辑并重新发送；确认编辑后其后的旧历史被替换，助手消息的复制、翻译、重新生成和朗读操作可用。
- 检查输入框垂直拖拽、聊天底部操作区、移动端与窄桌面无横向溢出和文字重叠。
- 检查实时通话的建连状态、字幕、输入输出音量、静音和挂断。
- 检查 PWA 安装、Service Worker 注册、网络失败时的应用壳回退，以及 API 不被缓存。

### 9.3 真实服务验收

- 文本流式对话：配置 Ark 后确认 SSE `delta` 增量、`done` 结束事件和异常 `error` 事件。
- TTS：确认豆包 Chunked 音频可播放；未授权、额度不足和音色错误返回可理解的 `503`；一般上游错误返回 `502`；带 `actionUrl` 的错误可定位到豆包控制台。
- 语音输入：确认 16 kHz PCM 发送、ASR 字幕合并和不自动发送。
- 实时通话：确认按音色前缀选择正确模型版本、WebSocket 建连、ASR 字幕、TTS 播放、静音和挂断。
- 公网环境：部署后访问 `https://visionvoice.cn/sparkchat/`，分别检查网页、API、TTS 和实时语音，并记录响应头 `X-Tt-Logid`。

## 10. 部署配置

生产环境至少配置：

```dotenv
DOUBAO_SPEECH_API_KEY=...
ARK_API_KEY=...
ARK_MODEL=doubao-seed-character-260628
FLASK_SECRET_KEY=请使用稳定的长随机字符串
DOUBAO_REALTIME_RESOURCE_ID=volc.speech.dialog
DOUBAO_REALTIME_PUBLIC_WS=/sparkchat/realtime
SPEECH_ENGINE_PORT=3101
CLIENT_PORT=3002
CLIENT_HOST=127.0.0.1
COOKIE_SECURE=true
```

Web 服务和实时代理必须分别启动。Nginx 将公网 `/sparkchat/` 转发到 Web 服务，将 `/sparkchat/realtime` 以 WebSocket 方式转发到实时代理，并设置足够长的 `proxy_read_timeout`。部署同步应通过 Git 远端或服务器上的受控发布流程完成；部署后重新执行自动化测试和真实语音验收。
